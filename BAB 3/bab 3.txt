BAB III
METODOLOGI PENELITIAN

Bab ini menjabarkan metodologi penelitian yang digunakan untuk menjawab perumusan masalah pada Bagian 1.3. Pendekatan yang dipilih adalah penelitian kuantitatif eksperimental dengan kerangka pengukuran Goal–Question–Metric (Basili et al., 1994; Wohlin et al., 2024) yang diperluas dengan Three-Dimensional Evaluation Framework untuk Large Language Model terkuantisasi (Jin et al., 2024). Disiplin pengukuran mengadopsi praktik benchmarking ala MLPerf Inference (warm-up dipisah, run berulang, mean ± standar deviasi) dan dokumentasi reproducibility mengikuti NeurIPS Reproducibility Checklist (NeurIPS, 2024).

3.1.	Tahapan Penelitian
Penelitian dilaksanakan dalam delapan tahap berurutan sebagaimana diilustrasikan pada Gambar 3.1.

[GAMBAR 3.1] Tahapan penelitian (waterfall eksperimental). Sumber: gambar/3.1_tahapan_penelitian.png

a.	Studi Pustaka. Penelusuran literatur dilakukan pada jurnal bereputasi yang diterbitkan dalam rentang 2020–2026, mencakup metode kuantisasi, evaluasi LLM, edge intelligence, dan arsitektur SLM. Hasil studi pustaka dirangkum di BAB II.
b.	Perencanaan Goal–Question–Metric (GQM). Tujuan penelitian (Goal) diturunkan menjadi empat pertanyaan riset (Question) sesuai Bagian 1.3, lalu setiap pertanyaan dipetakan ke metrik kuantitatif (Metric) sebagaimana dirinci pada Bagian 3.4 dan diilustrasikan pada Gambar 3.3.
c.	Persiapan Model dan Lingkungan Eksperimen. Bobot LFM2.5-1.2B-Base dan Qwen3.5-2B diunduh dari Hugging Face, dikonversi ke GGUF, dan dikuantisasi ke Q5_K_M, Q4_K_M, dan Q3_K_M menggunakan utilitas llama.cpp quantize. Hasilnya berupa delapan file GGUF (2 model × 4 varian).
d.	Pengukuran Statik. File size (MB) dicatat dari sistem berkas. Peak RAM dicatat saat model dimuat ke memori namun belum dieksekusi.
e.	Pengukuran Dinamik. Prompt processing rate dan generation rate diukur menggunakan utilitas llama-bench dengan prompt panjang 512 token dan output 128 token, lima ulangan plus dua warm-up.
f.	Pengukuran Kualitas. Perplexity dihitung pada dataset WikiText-2 (split test, 512 token sliding window — default `llama-perplexity` llama.cpp). Akurasi MMLU, GSM8k, dan HumanEval dihitung pada 100 sampel random per dataset menggunakan evaluator script.
g.	Analisis Pareto dan Statistik. Hasil seluruh pengukuran diagregasi pada Python (pandas), kemudian dianalisis dengan diagram radar, diagram Pareto, dan uji Wilcoxon signed-rank (α = 0,05) terhadap baseline FP16.
h.	Pelaporan dan Validasi. Hasil ditulis di BAB IV. Validasi dilakukan dengan re-run subset (10% kondisi) untuk memastikan reprodusibilitas.

3.3.	Metode Pengumpulan Data
Pengumpulan data dilakukan melalui tiga metode utama berikut, sesuai panduan BSI.

a.	Observasi. Observasi dilakukan secara terotomasi melalui System Benchmarking Logging dengan menjalankan llama-bench dan skrip evaluator pada Termux. Tiga sumber log direkam: (1) log sistem berupa pembacaan htop dan /proc/meminfo setiap 200 ms; (2) log engine berupa keluaran stdout llama.cpp yang berisi prompt eval rate (t/s), generation rate (t/s), dan perplexity; (3) log kualitas berupa jawaban model pada dataset MMLU, GSM8k, dan HumanEval yang dibandingkan dengan ground truth melalui skrip evaluator (regex/exact match). Seluruh log disimpan dalam format CSV dan ditarik ke laptop peneliti melalui adb pull untuk analisis lebih lanjut.

b.	Wawancara. Wawancara terstruktur dilakukan secara terbatas dan bersifat opsional terhadap dosen pembimbing teknis sebagai validator metodologi. Wawancara hanya bertujuan memvalidasi rancangan eksperimen, dan tidak menjadi sumber data primer.

c.	Studi Pustaka. Studi pustaka dilakukan dengan mengumpulkan dan mereview jurnal yang dipublikasikan dalam lima tahun terakhir, sebagaimana telah dirangkum pada BAB II. Manajemen referensi memakai Mendeley dengan format APA edisi ke-7.

Untuk menjamin ukuran sampel yang memadai, setiap kondisi (kombinasi model × varian kuantisasi × benchmark) dijalankan dengan dua warm-up run yang dipisahkan dari lima run pengukuran efektif (n = 5). Sampel pengujian terdiri dari dua model (LFM2.5-1.2B-Base dan Qwen3.5-2B), empat varian kuantisasi (FP16, Q5_K_M, Q4_K_M, Q3_K_M), empat benchmark sistem (file size, peak RAM, prompt t/s, generation t/s), serta empat benchmark kualitas (WikiText-2 PPL, MMLU, GSM8k, HumanEval) dengan 100 sampel per benchmark kualitas, sehingga total 160 run pengukuran sistem dan 32 run pengukuran kualitas. Jumlah ini memenuhi persyaratan statistik (Cohen's d = 0,3 dengan power 0,8 mensyaratkan n ≥ 65).

3.4.2.	Three-Dimensional Evaluation Framework
Hasil pengukuran kemudian diorganisasi ke dalam tiga dimensi evaluasi sesuai Jin et al. (2024) yang dijelaskan pada Bagian 2.1.7 dan diilustrasikan pada Gambar 3.4.

a.	Knowledge & Capacity → MMLU, GSM8k, HumanEval (akurasi).
b.	Alignment → Perplexity WikiText-2.
c.	Efficiency → file size, peak RAM, prompt t/s, generation t/s.

3.4.3.	Statistik Inferensial
Untuk membandingkan setiap varian Qx_K_M dengan baseline FP16 pada metrik dinamik (TPS, RAM), digunakan uji Wilcoxon signed-rank (paired non-parametric, n = 5 per kondisi) dengan tingkat signifikansi α = 0,05. Pemilihan uji non-parametrik didasarkan pada ukuran sampel kecil dan tidak adanya jaminan normalitas. Effect size dilaporkan sebagai r = Z/√N.

3.4.4.	Analisis Pareto
Analisis Pareto memetakan trade-off antara dua sumbu utama, biasanya storage (sumbu X, lebih kiri = lebih baik) dan composite accuracy (sumbu Y, lebih atas = lebih baik). Marker size dipakai sebagai dimensi ketiga yang merepresentasikan peak RAM. Varian yang berada pada Pareto frontier dianggap tidak terdominasi (Pareto-optimal) dan menjadi rekomendasi akhir penelitian.

3.4.5.	Reproducibility dan Threats to Validity
Mengikuti NeurIPS Reproducibility Checklist (NeurIPS, 2024), seluruh konfigurasi eksperimen didokumentasikan: nama dan tag versi model, hash file GGUF (SHA256), prompt set yang dipakai, parameter sampling (temperature = 0, top_k = 1, top_p = 1), governor CPU (performance), suhu ambient, dan random seed (untuk shuffle dataset). Threats to validity dianalisis pada empat kategori (Wohlin et al., 2024):
1.	Internal validity: variasi suhu perangkat dan thermal throttling—dimitigasi dengan jeda cooldown 60 detik antar run.
2.	External validity: hasil mungkin tidak generalisasi ke SoC lain. Dimitigasi dengan deklarasi eksplisit batasan hardware pada Bagian 1.7.
3.	Construct validity: PPL bisa tidak korelat dengan akurasi. Dimitigasi dengan menyertakan tiga benchmark kapabilitas (MMLU, GSM8k, HumanEval) sebagai triangulasi.
4.	Conclusion validity: ukuran sampel kecil dapat memunculkan false positive. Dimitigasi dengan uji non-parametrik dan effect size.
